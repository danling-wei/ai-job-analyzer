## 1. Project at a glance

**Goal.** Given a job title (e.g. _"Senior ML Engineer"_), run an agentic
workflow that:

1. Scrapes matching postings from multiple job boards.
2. Uses an LLM to extract the **job description (JD)** and **responsibilities**.
3. Distills the **key tech stack** and **core competencies** required for the
   role, with frequency / importance signals and supporting evidence.

**Non-goals (for now).** Resume matching, automated apply, salary prediction.

**Audience.** Job seekers preparing for a role; recruiters benchmarking JDs.

## 2. Tech choices

| Layer            | Choice                                                          | Why                                                                       |
| ---------------- | --------------------------------------------------------------- | ------------------------------------------------------------------------- |
| Package manager  | **uv**                                                          | Fast, lockfile-first, recommended by user.                                |
| Language         | Python `>=3.11,<3.14`                                           | Pin range, target 3.11 for typing/perf parity with deploy.                |
| Web framework    | **FastAPI + uvicorn**                                           | Async-native, OpenAPI for free, ideal for streaming LLM output later.     |
| Validation       | **pydantic v2 + pydantic-settings**                             | Shared schema between API, agent, and storage.                            |
| Agent runtime    | **LangGraph** (`langgraph`, `langchain-core`, `langchain-openai`) | Stateful, branching workflows with retries / human-in-the-loop hooks.   |
| Scraping         | **httpx + BeautifulSoup + lxml**, **Playwright** for JS sites   | httpx for simple JSON / static pages; Playwright when JS rendering needed. |
| Resilience       | **tenacity**                                                    | Per-scraper / per-LLM retry policies.                                     |
| Logging          | **loguru**                                                      | One-line setup, intercepts stdlib + uvicorn loggers.                      |
| CLI              | **typer + rich**                                                | `serve` and `analyze` commands without re-implementing argparse.          |
| Tests            | **pytest + pytest-asyncio + respx**                             | Async-first, HTTP mocking for scrapers.                                   |
| Lint / format    | **ruff** (lint + format)                                        | Single tool, fast.                                                        |
| Type-check       | **mypy --strict**                                               | Run on `src/` only (tests/ and frontend/ excluded).                       |
| Frontend         | Single-file **vanilla HTML + Tailwind CDN + JS**, served by FastAPI | Zero npm / build, zero CORS (same-origin). Streams workflow via SSE. Easy to swap for Next.js later. |

LLM provider is configurable
(`LLM_PROVIDER=openai|anthropic|ollama|qwen_lora|qwen_service|mock`) and defaults to `mock`
so the project runs offline out of the box. `qwen_lora` loads a local Qwen
instruct model plus an optional PEFT LoRA adapter in-process. `qwen_service`
calls the standalone Qwen model service under `model_lab/server/`, keeping the
application process CPU/lightweight.
When `LLM_PROVIDER=qwen_service`, `FINALIZER_PROVIDER` can be set to
`qwen_service`, `openai`, or `mock`. The recommended hybrid mode is local Qwen
for per-JD skill extraction and OpenAI for low-frequency skill canonicalization
plus final summary/responsibility synthesis.

## 4. Architecture (after M1.5)

```
                  ┌────────────────┐
                  │  Browser /ui/  │      WorkflowEvent stream
                  │  vanilla JS    │◀──────────────────────────┐
                  └────────┬───────┘                           │
                           │ POST /analyze/stream              │ Server-Sent Events
                           ▼                                   │
   ┌───────────────────────────────────────┐                   │
   │ FastAPI                               │                   │
   │  /healthz   /sources                  │                   │
   │  /analyze        (1-shot JSON)        │                   │
   │  /analyze/stream (SSE)  ──────────────┼───────────────────┘
   │  /ui/...        (StaticFiles)         │
   └────────┬──────────────────────────────┘
            │ AnalysisRequest
            ▼
   ┌───────────────────────────────────────┐    yields WorkflowEvent(...)
   │ agents.workflow.run_analysis_events   │ ──────────────────────────────▶ SSE
   │  1. plan                              │
   │  2. scrape   (async, as_completed)    │
   │  3. dedupe                            │
   │  4. extract  (LLM / Mock)             │
   │  5. result                            │
   └───────────────────────────────────────┘
```

### WorkflowEvent types

| `type`                   | When                               | Notable `data` keys                                  |
| ------------------------ | ---------------------------------- | ---------------------------------------------------- |
| `plan:start`             | Pipeline begins                    | `job_title`, `location`, `sources_requested`         |
| `plan:done`              | Sources resolved                   | `sources`, `max_per_source`, `llm_provider`          |
| `scrape:start`           | Concurrent scrape kicks off        | `sources`                                            |
| `scrape:source:start`    | All scraper tasks launched         | `sources`                                            |
| `scrape:source:done`     | One scraper finished (any source)  | `source`, `count`, `postings_so_far`                 |
| `scrape:source:error`    | One scraper failed                 | `source`, `error`                                    |
| `scrape:done`            | All scrapers finished              | `total`                                              |
| `dedupe:start`           | Before dedupe                      | `input`                                              |
| `dedupe:done`            | After dedupe                       | `before`, `after`, `removed`                         |
| `extract:start`          | Before LLM call                    | `extractor`, `provider`, `model`, `postings`         |
| `extract:done`           | After LLM call                     | `top_skills`, `responsibilities`, `nice_to_have`     |
| `result`                 | Terminal event on success          | full `AnalysisResult` (model_dump)                   |
| `fatal`                  | Pipeline aborted                   | `stage`, `error`                                     |

`run_analysis_events()` is the canonical pipeline; `run_analysis()` simply
drains it and returns the final `AnalysisResult` (used by the CLI and the
non-streaming `POST /analyze`).

* Scrapers cache raw upstream payloads under
  `${CACHE_DIR}/<source>/<YYYY-MM-DD>/<slug>.json`. Re-runs and tests are
  offline-friendly.
* SerpApi Google Jobs returns roughly 10 jobs per page; the scraper follows
  `serpapi_pagination.next_page_token` until `max_per_source` is reached.
* `LLMExtractor` uses `langchain-openai` (or `langchain-anthropic`,
  `langchain-ollama`) with `with_structured_output(_LLMOutput)` so the model
  returns a typed payload that we merge into `AnalysisResult`.
  `top_skills` is intentionally treated as a concrete technology stack list:
  the prompt asks for job-seeker skill-gap items that are learnable and
  portfolio-verifiable (tools, platforms, methods, product analytics, model/API
  providers), and post-processing filters generic labels like AI, machine
  learning, cloud platforms, APIs, UX, collaboration, automation, project
  management, and communication. Final skills are sorted by descending mention
  frequency, with importance used only as a tie-breaker.
* `QwenLoRAExtractor` is available via `LLM_PROVIDER=qwen_lora` for in-process
  loading. `QwenServiceExtractor` is available via `LLM_PROVIDER=qwen_service`
  and calls `QWEN_SERVICE_URL` (default `http://127.0.0.1:8010`), so Qwen can
  run as a separate GPU/model process. The service starts with
  `uv run ai-job-analyzer serve-qwen` and loads `QWEN_BASE_MODEL` plus optional
  `QWEN_ADAPTER_PATH`.
  `QwenServiceExtractor` sends postings to Qwen in small batches
  (`QWEN_SERVICE_BATCH_SIZE`, normally `1`) and treats Qwen as the high-volume
  skill extractor. Final low-volume cleanup is controlled by
  `FINALIZER_PROVIDER`: `qwen_service` calls the Qwen service endpoints
  `/canonicalise-skills` and `/synthesise`; `openai` uses `FINALIZER_MODEL`
  through `langchain-openai`; `mock` skips LLM cleanup and keeps the merged
  Qwen result.
* `build_extractor()` silently degrades to `MockExtractor` when the configured
  provider is unusable (missing API key, missing optional dep, runtime
  exception). The pipeline never hard-fails on LLM issues.

Stages are still plain async functions; they will become LangGraph nodes in
M2 once we add (a) per-stage retries with `tenacity`, (b) optional human
review checkpoint between `dedupe` and `extract`, and (c) streaming progress
events to the client.

## 5. Conventions

- **Imports** sorted by ruff (`I`); use `from __future__ import annotations`
  in every module that ships type hints.
- **Async by default** for scrapers, extractors, and routes. Sync helpers are
  fine for pure CPU work (e.g. `_dedupe`).
- **Errors:** scrapers must never raise out of `search()`; log + return `[]`.
  Validation errors and config errors propagate.
- **Schemas first.** New data flowing between layers goes through a pydantic
  model in `models/`; do not pass raw dicts across module boundaries.
- **Secrets** only via `.env` / environment, never hardcoded. Keep
  `.env.example` in sync when adding new settings.
- **Tests** live in `tests/`, mirror the `src/` layout, use `respx` for HTTP
  mocking, never hit the real internet by default.
- **Commits** small and topical; conventional-commits style preferred
  (`feat:`, `fix:`, `chore:`, `docs:`).

## 6. Common commands

```bash
# install / sync deps (creates .venv automatically)
uv sync

# install dev tools too
uv sync --group dev

# run the API (auto-reload)
uv run ai-job-analyzer serve --reload

# one-off CLI analysis (mock + mock by default)
uv run ai-job-analyzer analyze "Senior ML Engineer" --source mock

# API-backed job sources (require matching .env credentials)
uv run ai-job-analyzer analyze "Python Backend" --source serpapi

# real scrape + real OpenAI LLM
# (requires LLM_PROVIDER=openai and OPENAI_API_KEY in .env)
uv run ai-job-analyzer analyze "Python Backend" --source serpapi

# local fine-tuned Qwen LoRA extractor
uv sync --extra qwen-lora
uv run python model_lab/scripts/finetune_qwen_lora.py --train model_lab/data/examples/qwen_skill_train.example.jsonl --output model_lab/models/qwen-job-keyword-lora
LLM_PROVIDER=qwen_lora QWEN_ADAPTER_PATH=model_lab/models/qwen-job-keyword-lora uv run ai-job-analyzer analyze "Applied AI Engineer" --source serpapi

# split-process Qwen service + application
uv run ai-job-analyzer serve-qwen
LLM_PROVIDER=qwen_service uv run ai-job-analyzer serve --reload

# hybrid mode: Qwen extracts per-JD skills; OpenAI canonicalizes and summarizes
LLM_PROVIDER=qwen_service FINALIZER_PROVIDER=openai FINALIZER_MODEL=gpt-5.5 uv run ai-job-analyzer serve --reload

# tests / lint / types
uv run pytest
uv run ruff check .
uv run ruff format .
uv run mypy src

# add a runtime dep
uv add <package>

# add a dev-only dep
uv add --group dev <package>

# install Playwright browsers (only needed once, before using JS scrapers)
uv run playwright install chromium
```
